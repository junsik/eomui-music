# 구조

## 전체 흐름

```
[YouTube 영상 페이지]
        │
        │  사용자가 빨간 "MP3 다운로드" 버튼 클릭
        ▼
[Chrome 확장 content.js]
        │
        │  fetch("http://127.0.0.1:8080/api/download?url=...")
        │  헤더: X-Eomui-Client: 1
        ▼
[Go 앱 — 트레이에서 실행 중]
        │
        │  yt-dlp (+ deno) 로 음원 추출 → ffmpeg 로 MP3 변환
        ▼
[바탕화면에 저장] → [정리 규칙에 따라 보관함으로 이동]
```

## 구성 요소

### app/ — Go 데스크톱 앱

창이 없는 GUI 서브시스템 프로그램입니다 (`-H windowsgui`).
트레이 아이콘만 띄우고 로컬 HTTP 서버를 돌립니다.

| 파일 | 역할 |
|---|---|
| `main.go` | HTTP 핸들러, 트레이 메뉴, 다운로드 흐름 |
| `bootstrap.go` | 첫 실행 시 yt-dlp/ffmpeg/deno 확인·다운로드, 진행 상태 |
| `library.go` | 받은 곡 목록, 바탕화면 정리 규칙, 중복 판정 |
| `updater.go` | yt-dlp 주기적 자동 갱신 |
| `console_*.go` | 콘솔 출력 확보 (Windows는 AttachConsole/AllocConsole) |
| `dialog_*.go` | 확인·안내 대화상자 (Windows는 MessageBoxW) |
| `autostart_*.go` | 로그인 시 자동 실행 등록 (HKCU Run 키) |
| `instance_*.go` | 중복 실행 방지 (이름 있는 뮤텍스) |

`_windows.go` / `_other.go` 쌍은 빌드 태그로 나뉩니다.
Windows 전용 기능은 다른 OS에서 무해한 대체 구현을 씁니다.

### extension/ — Chrome 확장 (Manifest V3)

`content.js`가 YouTube의 `#top-level-buttons-computed` 액션바를 찾아
빨간 버튼을 주입합니다. SPA 네비게이션으로 액션바가 늦게 나타나면
500ms 간격으로 최대 30회 재시도합니다.

### installer/ — Inno Setup 설치 프로그램

`build.ps1`이 외부 실행 파일을 `bundle/`에 준비하고, Go 앱을 빌드한 뒤
`eomui-music.iss`를 컴파일합니다.

## 음악 목록 화면

받은 곡을 큰 글씨로 보여 주고 눌러서 듣게 해 주는 화면입니다.
`app/ui.html`을 `//go:embed`로 넣어 `/`에서 서빙합니다.

**네이티브 GUI 툴킷을 쓰지 않았습니다.** Fyne·Wails·webview는 모두 cgo가 필요해
"cgo 없이 exe 하나" 구조가 깨지고, 바이너리가 30~40MB 늘어나며,
한글 폰트와 DPI를 따로 다뤄야 합니다. Walk는 cgo가 없지만 관리가 멈춰 있습니다.

이미 로컬 HTTP 서버가 있으므로 HTML이 훨씬 간단하고, **화면 배율과 브라우저
글꼴 설정을 그대로 따라간다**는 이점까지 있습니다. 크기 단위를 `rem`으로 두어
배율 150%면 화면도 그만큼 커집니다.

### 화면이 쓰는 API

| 경로 | 하는 일 |
|---|---|
| `GET /api/songs?offset&limit` | 최신순 곡 목록 일부와 전체 개수 |
| `GET /api/play?path=` | 기본 음악 앱으로 곡 열기 |
| `GET /api/open-folder` | 음악 폴더 열기 |
| `POST /api/tidy` | 바탕화면 정리 |
| `GET /api/status` | 준비 상태와 진행률 |

곡이 수백 개여도 첫 화면이 짧도록 20곡씩 나눠 보냅니다.

**재생은 서버가 대신 엽니다.** 브라우저는 로컬 파일을 실행할 수 없으므로,
화면이 `/api/play`를 부르고 서버가 `explorer.exe <파일>`로 엽니다.
Windows 파일 연결에 등록된 기본 음악 앱이 실행되는 것을 실제로 확인했습니다
(폴더가 열리는 것이 아닙니다).
이때 **`music-index.json`에 있는 곡인지 반드시 확인합니다.** 확인하지 않으면
로컬 서버가 임의 파일 실행 통로가 됩니다.

화면의 요청도 확장과 똑같이 `X-Eomui-Client` 헤더를 붙입니다.
같은 출처 요청은 `Origin`이 붙지 않아 헤더가 없으면 막히기 때문입니다.

### 화면을 여는 방법

바로가기는 `eomui-music.exe -open`으로 실행합니다.

- 꺼져 있으면 → 프로그램이 시작되면서 화면이 열림
- 이미 켜져 있으면 → 두 번째 인스턴스가 화면만 열고 조용히 종료

`.url` 인터넷 바로가기도 검토했지만, 프로그램이 꺼져 있을 때
브라우저 연결 오류가 나서 쓰지 않았습니다.

자동 실행(Run 키)에는 `-open`을 붙이지 않습니다.
로그인할 때마다 브라우저가 뜨면 안 되기 때문입니다.

## 설치 위치

**`%LOCALAPPDATA%\Programs\어무이음악\`** 입니다. Program Files가 아닙니다.

이유가 두 가지입니다.

1. **쓰기 권한이 필요합니다.** 앱은 자기 폴더에 로그·설정·곡 목록을 쓰고,
   번들이 없는 배포본이라면 yt-dlp/ffmpeg(약 170MB)를 내려받습니다.
   Program Files는 쓰기가 막혀 있어 첫 실행이 실패하고,
   창이 없는 프로그램이라 **원인조차 보이지 않습니다.**
2. **UAC 창이 뜨지 않습니다.** 시니어 사용자에게 권한 상승 창은 그 자체가 장벽입니다.

VS Code·Slack과 같은 방식입니다.

## 자동 실행

`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`에 등록합니다.

검토했던 다른 방법:

- **Windows 서비스 — 쓸 수 없습니다.** Vista 이후 서비스는 세션 0에 격리되어
  있어 트레이 아이콘을 띄울 수도, 사용자 화면에서 음악 앱을 실행할 수도 없습니다.
  이 앱의 구조와 근본적으로 맞지 않습니다.
- **작업 스케줄러 — 동작하지만 불필요합니다.** 관리자 권한·지연 실행·실패 시 재시작
  같은 장점이 이 앱에는 해당이 없고, `schtasks` 의존과 제거할 작업 항목만 늘어납니다.

Run 키는 관리자 권한이 필요 없고 사용자 세션에서 실행되어 트레이가 정상 동작합니다.

## 중복 실행 방지

두 벌이 뜨면 두 번째는 포트 8080을 잡지 못합니다. 그런데 트레이 아이콘은
정상적으로 떠 있어서 **겉보기에는 멀쩡한데 아무것도 안 되는 상태**가 됩니다.
실제로 개발 중에 이 상황을 겪었습니다.

이름 있는 뮤텍스(`EomuiMusicSingleInstance`)로 막고, 이미 실행 중이면
안내 창을 띄운 뒤 종료합니다. 설치 프로그램도 같은 이름을 `AppMutex`로 보고
"실행 중이니 종료해 주세요"를 안내합니다.

포트 바인딩이 실패한 경우에도 트레이 툴팁에 원인을 표시합니다.
준비 작업이 나중에 끝나면서 오류 문구를 덮어쓰지 않도록,
치명적 오류는 한 번 걸리면 고정됩니다.

## 보안 모델

로컬에서만 도는 프로그램이라도 브라우저가 접근할 수 있는 HTTP 서버는
공격 면이 됩니다.

**1. `127.0.0.1`에만 바인딩합니다.**
`:8080`으로 열면 `0.0.0.0` 바인딩이라 같은 공유기에 붙은 다른 기기가
사용자 바탕화면에 파일을 쓸 수 있습니다.

**2. `/api/download`는 우리 확장의 요청만 받습니다.**
다음 중 하나를 만족해야 합니다.

- `X-Eomui-Client` 헤더가 있음
- `Origin`이 YouTube 계열이거나 `chrome-extension://`

`<img src="http://127.0.0.1:8080/api/download?url=...">` 같은 요청은
커스텀 헤더를 붙일 수 없고 `Origin`도 보내지 않아 둘 다 만족시킬 수 없습니다.
헤더 **또는** Origin 조건이라 크롬이 어느 쪽을 보내든 확장은 통과합니다.

**3. CORS는 허용 목록 방식입니다.**
예전에는 `Access-Control-Allow-Origin: *`이었습니다.

**4. 오류 응답에 내부 경로를 담지 않습니다.**
yt-dlp의 stderr에는 로컬 경로가 섞여 있어, 정해 둔 문구만 내보내고
원본은 로그에만 남깁니다.

## 음악 정리 규칙

바탕화면에 남기는 조건은 **두 가지를 모두** 만족해야 합니다.

- 받은 지 `desktopKeepDays`(기본 30일) 이내
- 그중에서도 최신 `desktopKeepCount`(기본 12곡)까지

날짜 조건만으로는 부족합니다. 많이 받은 달에는 30일치가 50곡을 넘어
바탕화면이 그대로 넘칩니다. 특히 화면 배율이 150%면 한눈에 보이는 아이콘이
10~20개뿐이라 **개수 상한이 있어야 화면에 천장이 생깁니다.**

넘치는 곡은 `바탕화면\음악 보관함\2026년 07월\`로 내려갑니다.
월 폴더를 바탕화면에 직접 두지 않는 이유는, 그러면 1년에 12개씩 폴더가 쌓여
같은 문제가 반복되기 때문입니다. 월은 0으로 채워(`07월`) 이름순 정렬이
곧 시간순이 되게 합니다.

**안전장치** — 옮기는 것은 `music-index.json`에 기록된, 이 프로그램이 받은
파일뿐입니다. 사용자가 직접 둔 사진·문서·MP3는 절대 건드리지 않습니다.

정리는 시작할 때와 매 다운로드 후에 실행되며, 여러 번 돌려도 결과가 같습니다.

## 상태 파일

앱 폴더에 생깁니다. 모두 `.gitignore` 대상입니다.

| 파일 | 내용 |
|---|---|
| `settings.json` | 사용자가 고치는 설정 (정리 기준) |
| `music-index.json` | 받은 곡 목록 — 정리와 중복 판정의 근거 |
| `state.json` | 마지막 yt-dlp 갱신 확인 시각 |
| `eomui-music.log` | 실행 로그 |
| `tmp/` | 변환 중 임시 파일 (10분 지나면 정리) |

## yt-dlp 자동 갱신

yt-dlp는 YouTube가 바뀔 때마다 깨지고 그때마다 새 버전이 나옵니다.
설치 시점 버전을 그대로 두면 몇 주 뒤 버튼이 안 먹는 날이 오는데,
어머니는 고치실 수 없습니다.

주 1회, 시작할 때 `yt-dlp -U`(자가 업데이트)를 실행합니다.
직접 내려받지 않고 공식 경로를 쓰므로 배포 형식이 바뀌어도 따라갑니다.

교체는 **`toolsReady`를 켜기 전에** 합니다. 그래야 다운로드 요청이 아직
막혀 있는 동안 실행 파일이 바뀌고, 사용 중인 exe를 덮어쓰지 않습니다.

갱신에 실패해도 치명적이지 않습니다. 기존 버전으로 계속 동작하고,
매 시작마다 재시도해 느려지지 않도록 확인 시각은 갱신합니다.

## 알려진 제약

- **코드 서명이 없습니다.** 설치 파일 실행 시 SmartScreen 경고가 뜹니다.
- **Chrome 확장은 수동 등록이 필요합니다.** 레지스트리로 외부 확장을 넣는
  방법이 있지만 웹스토어 밖 확장은 크롬이 비활성화시켜 실용성이 없습니다.
- **Windows 전용입니다.** 다른 OS에서도 빌드는 되지만 트레이·대화상자·
  자동 실행이 동작하지 않습니다.
